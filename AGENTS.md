# Working on Soniaa’s portfolio

- Read `PROJECT_REQUIREMENTS.md`, `ARCHITECTURE.md` and `PROGRESS.md` before making changes. Start from the current milestone and preserve the chosen design and content sources.
- Work in normal chat where possible. Use a coding tool for an actual file change, build, test or requested artifact. Prefer one engineer and one scoped change. Use a separate agent only for a genuinely independent task that justifies it.
- Divide work into milestones. For a bug, reproduce the symptom, edit only the affected files and run a focused regression check. Preserve working routes, stored data and mobile behavior.
- Update existing files in place. Include exact paths and runnable commands. Keep working code, verification results and pending work distinct. Maintain these four project files when decisions or milestones change.
- Keep credentials server-side. The local preview should run without private keys, cloud accounts or real email. Keep generated data, build output, dependency folders and real environment files out of milestone ZIPs.
- For a milestone, run the applicable tests and production build, record the results in `PROGRESS.md`, give a Git commit command and create a source ZIP when requested. Do not perform public deployment or change the site audience without the user’s instruction.
- For a new conversation, attach the latest ZIP, identify the milestone in `PROGRESS.md` and describe the next change. Ask for missing information only when it blocks that change.
